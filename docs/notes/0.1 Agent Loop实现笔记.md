# 实现概述

这一阶段从基础聊天循环出发，逐步实现 mo-code 的最小 Agent Loop，重点说明消息数组如何维护、模型如何发起工具调用、工具结果如何回传，以及如何使用本地 Mock 完成端到端测试。它建立了 Agent 的核心运行机制：模型负责判断下一步，程序负责执行工具并反馈结果，双方循环协作直到任务完成。

我们以 Claude Code（下文简称 CC）的 [agentic loop](https://code.claude.com/docs/en/how-claude-code-works#the-agentic-loop) 作为行为基线，并遵循 [Anthropic Tool Use 协议](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)组织 `tool_use`、`tool_result` 和消息历史。本阶段只实现可运行、可观察的最小循环；流式输出、权限控制和上下文管理留到后续扩展。

# 1. 最基础：聊天循环
这是最基础的聊天循环，还不是完整的 Agent Loop。它只负责维护对话上下文：

1. 将用户的新消息追加到 messages 队列里
2. 调用 LLM 获取响应
3. 将 LLM 的完整响应追加回 messages 队列里

```ts
async function chatOnce(messages, userMessage) {
  messages.push({ role: "user", content: userMessage });

  const response = await client.messages.create({
    model: "claude-...", // 例如："claude-sonnet-4-6"
    max_tokens: 4096,
    messages,
  });

  const text = response.content.find(b => b.type === "text")?.text ?? "";
  console.log(text); //打印响应信息

  messages.push({ role: "assistant", content: response.content });
}
```

# 2. 加上工具调用
这个其实很简单，我们只需要：
1. 在请求时加上一个参数，将我们定义的工具告诉AI
2. 如果AI决定调用工具，响应里会包含 tool_use block，可能有一个或多个
3. 依次执行这些需要执行的工具
4. 将工具的响应结果补充到消息队列里
5. 循环，直到某一轮不再返回 tool_use，说明进入最终阶段，循环可以结束

```ts
async function chat(messages, userMessage) {
  messages.push({ role: "user", content: userMessage });

  while (true) {
    const response = await client.messages.create({
      model: "claude-...",
      max_tokens: 4096,
      messages,
      tools: toolDefinitions,   // 注意这一行，定义工具清单
    });
    messages.push({ role: "assistant", content: response.content });

    // 挑出模型这一轮想调用的工具
    const toolUses = response.content.filter(b => b.type === "tool_use");
    if (toolUses.length === 0) break;   // 如果没有需要调用的工具，则认为任务完成，退出

    // 依次执行，收集工具执行结果
    const toolResults = [];
    for (const toolUse of toolUses) {
      printToolCall(toolUse.name, toolUse.input);
      const result = await executeTool(toolUse.name, toolUse.input);
      printToolResult(toolUse.name, result);
      toolResults.push({ type: "tool_result", tool_use_id: toolUse.id, content: result });
    }

    // 将工具结果补充到消息队列里，作为新的消息，AI继续思考
    // 在 Anthropic 消息格式里，工具结果是作为 user 消息返回给模型的。
    messages.push({ role: "user", content: toolResults }); 
  }
}
```

# 3. 实现落地
分为5个部分：
1. 类型定义
2. MODEL、SYSTEM_PROMPT、toolDefinitions 定义
3. AnthropicLikeClient 定义
4. Agent 定义——最重要，下面专门说这个
5. 工具执行和CLI调用

其他的部分比较简单，或者不是这次重点，推荐直接看源码：src/agent-loop.ts

下面重点说一下 Agent 定义，和第2版其实非常相近，主要区别在于：
1. messages 和 client 放进类里面管理
2. 补充了 process 相关的运行时处理：从环境变量读取 mock 服务地址、从命令行参数读取用户输入，并把模型文本输出到终端。

```ts
export class Agent {
  private client: AnthropicLikeClient;
  private messages: Message[] = [];

  constructor(baseURL = process.env.ANTHROPIC_BASE_URL ?? "http://127.0.0.1:3000") {
    this.client = new AnthropicLikeClient(baseURL);
  }

  async chat(userText: string): Promise<void> {
    this.messages.push({ role: "user", content: userText });

    while (true) {
      const request = {
        model: MODEL,
        max_tokens: 4096,
        system: SYSTEM_PROMPT,
        tools: toolDefinitions,
        messages: this.messages,
      };

      const reply = await this.client.messages.create(request);
      for (const block of reply.content) {
        if (block.type === "text") process.stdout.write(block.text);
      }
      process.stdout.write("\n");

      this.messages.push({ role: "assistant", content: reply.content });

      const toolUses = reply.content.filter((block): block is ToolUseBlock => block.type === "tool_use");
      if (toolUses.length === 0) return;

      const results: ToolResultBlock[] = [];
      for (const toolUse of toolUses) {
        console.log(`  -> ${toolUse.name}(${JSON.stringify(toolUse.input)})`);
        const output = await executeTool(toolUse.name, toolUse.input);
        results.push({ type: "tool_result", tool_use_id: toolUse.id, content: output });
      }

      this.messages.push({ role: "user", content: results });
    }
  }
}
```

## 本地测试
> 以下操作都在项目根目录

1. 启动本地 mock Anthropic服务
```shell
node mock/mock-llm.mjs
```

输出类似这样（端口号会变）：
```shell
Mock Anthropic listening on http://127.0.0.1:60007
```

复制这里出现的 URL，或者只替换命令里的端口号。

2. 准备文件测试 Agent Loop

将端口号替换，然后执行
```shell
echo "hello from agent loop" > greeting.txt
ANTHROPIC_BASE_URL=http://127.0.0.1:60007 \
  node --experimental-strip-types src/agent-loop.ts "Read the file greeting.txt and tell me what it says."
```

执行结果是：
```shell
  -> read_file({"file_path":"greeting.txt"})
greeting.txt says:
hello from agent loop
```

同时根目录会出现 `greeting.txt` 文件，内容是：hello from agent loop

解释下：
```shell
# 在当前目录创建一个 greeting.txt 文件（存在则覆盖），并写入内容：hello from agent loop
echo "hello from agent loop" > greeting.txt

# 设置临时变量信息；运行指定的ts文件；
# 这个是传入的信息："Read the file greeting.txt and tell me what it says."
# --experimental-strip-types 是让Node将TS的类型剥离后执行
ANTHROPIC_BASE_URL=http://127.0.0.1:60007 \
  node --experimental-strip-types src/agent-loop.ts "Read the file greeting.txt and tell me what it says."
```

核心流程：
1. `echo` 会在根目录创建 `greeting.txt` 文件，内容是：hello from agent loop
2. 启动 `Agent` 
3. `Agent` 将用户问题发给本地 `mock Anthropic`
4. `mock` 返回一个 `tool_use(read_file)`
5. `Agent` 执行 `read_file` ，读取 `greeting.txt`
6. `Agent` 将读取结果作为 `tool_result` 发给 `mock`
7. `mock` 返回最终回答

然后，你可以尝试下其他文件或输入测试（我已经试过了）：

```shell
echo "another file content" > notes.txt
ANTHROPIC_BASE_URL=http://127.0.0.1:60007 \
  node --experimental-strip-types src/agent-loop.ts "Read the file notes.txt"
```

## 消息数组的变化（以测试为例）
```ts
[
  {
    role: "user",
    content: "Read the file greeting.txt and tell me what it says."
  },
  {
    role: "assistant",
    content: [
      {
        type: "tool_use",
        id: "toolu_mock_0_0",
        name: "read_file",
        input: {
          file_path: "greeting.txt"
        }
      }
    ]
  },
  {
    role: "user",
    content: [
      {
        type: "tool_result",
        tool_use_id: "toolu_mock_0_0",
        content: "hello from agent loop\n"
      }
    ]
  },
  {
    role: "assistant",
    content: [
      {
        type: "text",
        text: "greeting.txt says:\nhello from agent loop\n"
      }
    ]
  }
]
```

依次是：
1. user 提交原始问题
2. assistant 调用工具
3. user 以 tool_result 的形式把工具执行结果返回给模型（通过 tool_use_id 关联）
4. assistant 完成任务，回复
