## read_file
```ts
type ToolDef = {
  name: string;
  description: string;
  input_schema: {
    type: "object";
    properties: Record<string, unknown>;
    required: string[];
  };
};

// src/tools/read-file.ts
export const readFileTool: ToolDef = {
  name: "read_file",
  description: "Read the contents of a file. Returns the file content with line numbers.",
  input_schema: {
    type: "object",
    properties: {
      file_path: { type: "string", description: "The path to the file to read" },
    },
    required: ["file_path"],
  },
};

// src/tools/index.ts
export const toolDefinitions = [readFileTool];
```

```ts
export function readFile(input: { file_path: string }): string {
  try {
    const content = readFileSync(input.file_path, "utf-8");
    return content
      .split("\n")
      .map((line, index) => `${String(index + 1).padStart(4)} | ${line}`)
      .join("\n");
  } catch (error) {
    return `Error reading file: ${error instanceof Error ? error.message : String(error)}`;
  }
}
```
核心思路：
1. 读取文件
2. 分行
3. 补充行号
4. 拼接返回
5. 异常兜底

为了保证稳定性，这里补充了单元测试，跑命令：`pnpm test` 即可验证

## write_file
> 从这部分开始不再重复说明 ToolDef 类型；每个工具仍建议补充对应单元测试。

```ts
function writeFile(input: { file_path: string; content: string }): string {
  try {
    const dir = dirname(input.file_path);
    if (!existsSync(dir)) mkdirSync(dir, { recursive: true });
    writeFileSync(input.file_path, input.content);
    return `Successfully wrote to ${input.file_path}`;
  } catch (e) {
    return `Error writing file: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```

核心思路：
1. 获取文件的目录
2. 如果父目录不存在，则创建
3. 将输入内容写入到文件
4. 输出写入成功的信息
5. 异常兜底

## edit_file
```ts
function editFile(input: { file_path: string; old_string: string; new_string: string }): string {
  try {
    if (input.old_string.length === 0) {
      return "Error: old_string must not be empty.";
    }
    const content = readFileSync(input.file_path, "utf-8");
    const count = content.split(input.old_string).length - 1;
    if (count === 0) {
      return `Error: old_string not found in ${input.file_path}`;
    }
    if (count > 1) {
      return `Error: old_string found ${count} times in ${input.file_path}. Must be unique.`;
    }
    // split().join() 比 replace() 更安全一点，因为它不会触发 $ 替换语义
    const updated = content.split(input.old_string).join(input.new_string);
    writeFileSync(input.file_path, updated);
    return `Successfully edited ${input.file_path}`;
  } catch (e) {
    return `Error editing file: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```
1. 如果 old_string 为空，直接返回错误
2. 读取指定文件的内容 content
3. content 如果不包含旧字符串，则报错没有找到
4. 如果出现多次，要求模型提供更多上下文来标识唯一修改点（宁失败也不猜测，静默匹配第一个要比告知失败危险的多）
5. 在确认旧字符串只出现一次后，将它替换为新字符串
6. 更新写入文件
7. 提示成功信息
8. 兜底报错

### 引号容错 + Diff 输出
基础版本只能做精确字符串匹配，但 LLM 有时会把直引号和弯引号混用，例如文件里是 `const msg = “hello”`，模型传入的是 `const msg = "hello"`。

所以先做引号标准化匹配，但真正替换时仍然使用文件中的原始字符串。

```ts
function normalizeQuotes(value: string): string {
  return value
    .replace(/[\u2018\u2019\u2032]/g, "'")
    .replace(/[\u201C\u201D\u2033]/g, '"');
}

function findActualString(fileContent: string, searchString: string): string | null {
  if (fileContent.includes(searchString)) return searchString;

  const normalizedFile = normalizeQuotes(fileContent);
  const normalizedSearch = normalizeQuotes(searchString);
  const index = normalizedFile.indexOf(normalizedSearch);

  if (index === -1) return null;
  return fileContent.slice(index, index + searchString.length);
}
```

注意：唯一性检查也要基于标准化后的字符串；如果标准化后出现多次，仍然要拒绝编辑，避免猜测修改位置。

另外再添加一个方法，用于在编辑成功后返回简易 diff，方便确认修改点：

```ts
function generateDiff(content: string, oldString: string, newString: string): string {
  const lineNumber = content.slice(0, content.indexOf(oldString)).split("\n").length;

  return [
    `@@ -${lineNumber},1 +${lineNumber},1 @@`,
    `- ${oldString}`,
    `+ ${newString}`,
  ].join("\n");
}
```

以上 3 个方法会在 `edit_file` 中使用，具体整合逻辑参见源码，这里不再展开。

## list_files

```ts
async function listFiles(input: { pattern: string; path?: string }): Promise<string> {
  try {
    const files = await glob(input.pattern, {
      cwd: input.path || process.cwd(),
      nodir: true,
      ignore: ["node_modules/**", ".git/**"],
    });

    if (files.length === 0) {
      return "No files found matching the pattern.";
    }

    return files.slice(0, 200).join("\n");
  } catch (e) {
    return `Error listing files: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```

核心思路：
1. 使用 glob pattern 根据参数匹配文件
    1. `pattern` 必填，用来描述要匹配的文件，例如 `*.ts`、`**/*.ts`、`src/**/*`
    2. `path` 可选，用来指定搜索基准目录，默认是当前工作目录
    3. 是否递归由 `pattern` 决定，不在工具里固定递归
    4. 只返回文件，不返回目录
    5. 忽略 `node_modules/**` 和 `.git/**`
2. 最多返回前 200 条，避免结果过长
3. 没有匹配文件时，返回空结果提示
4. 异常兜底

## grep_search
`grep_search` 用来在文件内容里搜索正则匹配项，返回包含文件路径、行号和匹配行的结果。

它适合回答“哪里定义了某个函数”“哪些文件引用了某个变量”这类问题。

```ts
function grepSearch(input: { pattern: string; path?: string; include?: string }): string {
  try {
    const args = ["--line-number", "--color=never"];
    if (input.include) args.push("-g", input.include);
    args.push("--", input.pattern);
    args.push(input.path || ".");

    const result = execFileSync("rg", args, {
      encoding: "utf-8",
      maxBuffer: 10 * 1024 * 1024,
      timeout: 10000,
    });

    const lines = result.split("\n").filter(Boolean);
    return lines.slice(0, 100).join("\n") +
      (lines.length > 100 ? `\n... and ${lines.length - 100} more matches` : "");
  } catch (e) {
    if (e.status === 1) return "No matches found.";
    if (e.code === "ENOENT") return "Error: ripgrep (rg) is not installed.";
    if (e.code === "ENOBUFS") {
      return "Error: too many matches to buffer; narrow the pattern, path, or include filter.";
    }
    return `Error: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```

核心思路：
1. 处理参数，参数说明：
    1. `pattern` 必填，表示要搜索的正则
    2. `path` 可选，表示搜索路径，默认是当前目录
    3. `include` 可选，用来限制文件类型，例如 `*.ts`
2. 使用 `rg --line-number` 搜索并返回行号
3. 最多返回前 100 条，避免结果过长
4. 异常兜底
    1. `rg` 退出码为 1 表示没有匹配，不算异常
    2. 如果没有安装 `rg`，返回明确错误
    3. 如果匹配结果过大导致 buffer 溢出，提示缩小搜索范围
    4. 默认兜底

为什么这里cc使用的是 `rg`（ripgrep）， 而不是系统 `grep`？原因是 `rg` 更适合代码搜索：
- 默认递归
- 默认尊重 .gitignore
- 默认跳过隐藏目录、二进制文件、node_modules 这类常见噪音更少
- 速度通常比 grep -r 快很多
- 输出格式天然适合代码搜索：path:line:match
- 跨平台体验更好

系统 `grep` 虽然更基础、通常自带，但需要额外处理递归、忽略目录和不同平台参数差异。

## run_shell
```ts
function runShell(input: { command: string; timeout?: number }): string {
  try {
    const result = execSync(input.command, {
      encoding: "utf-8",
      maxBuffer: 5 * 1024 * 1024,
      timeout: input.timeout || 30000,
      stdio: ["pipe", "pipe", "pipe"],
      shell: process.platform === "win32" ? "powershell.exe" : "/bin/sh",
    });

    return result || "(no output)";
  } catch (e: any) {
    const stderr = e.stderr ? `\nStderr: ${e.stderr}` : "";
    const stdout = e.stdout ? `\nStdout: ${e.stdout}` : "";
    if (e.code === "ETIMEDOUT" || (e.signal === "SIGTERM" && e.status === null)) {
      return `Command timed out after ${input.timeout || 30000}ms${stdout}${stderr}`;
    }
    if (typeof e.status === "number") {
      return `Command failed (exit code ${e.status})${stdout}${stderr}`;
    }
    return `Error: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```

核心思路：
1. 处理参数，参数说明：
    1. `command` 必填，表示要执行的 Shell 命令
    2. `timeout` 可选，单位是毫秒，默认 `30000`
2. `execSync` 执行
    1. 使用 Shell 执行命令；成功时返回 stdout，失败时从异常对象里取 stdout 和 stderr
    2. 使用 `maxBuffer` 限制输出大小，避免命令输出过大撑爆进程
3. 输出命令结果，如果没有内容则返回 `(no output)`
4. 异常兜底
    1. 命令失败时，同时返回 exit code、stdout 和 stderr
    2. 命令超时时，返回明确的 timeout 信息
    3. 默认兜底

注意：这个工具的能力边界比前几个工具大很多，因为它可以执行任意命令。

我们做了 timeout 和 maxBuffer 的处理，危险命令确认、权限规则、plan mode 禁止 shell 等安全逻辑放在后续权限系统里处理。

## 工具结果截断
工具执行结果最终会进入消息数组，继续发回给模型。结果太长会占用大量上下文，甚至影响后续模型调用。

因此可以在工具分发层统一做一次结果截断，而不是让每个工具都重复处理。

```ts
const MAX_RESULT_CHARS = 50000;

function truncateResult(result: string): string {
  if (result.length <= MAX_RESULT_CHARS) return result;

  const keepEach = Math.floor((MAX_RESULT_CHARS - 60) / 2);
  return (
    result.slice(0, keepEach) +
    `\n\n[... truncated ${result.length - keepEach * 2} chars ...]\n\n` +
    result.slice(-keepEach)
  );
}
```

核心思路：
1. 设置统一的工具结果长度上限
2. 未超过上限时直接返回
3. 超过上限时保留头部和尾部
4. 中间插入明确的截断提示，告诉模型有多少字符被省略
5. 在 `executeTool` 里统一调用，让所有工具都受保护

为什么保留头尾，而不是只保留开头？因为很多命令的关键结果在末尾，例如编译错误摘要、测试失败统计、最终 exit 信息等。

注意：这和 `grep_search` 自身最多返回前 100 条不冲突。`grep_search` 的限制是工具内部的业务截断；这里是工具结果进入消息数组前的统一兜底。

## 工具对象注册表
现在的 `executeTool` 使用 `switch` 分发工具调用。

工具少的时候这种写法足够直观，但随着工具变多，每新增一个工具都要同时改工具文件、`toolDefinitions` 和 `executeTool`，这就让开发和维护的负担增加了。

所以这里我们会改成注册的方式，可以保持工具的独立习惯，方便增加、删除和调整对应的工具

```ts
export const readFileTool = {
  name: "read_file",
  description: "Read the contents of a file. Returns the file content with line numbers.",
  input_schema: {
    type: "object",
    properties: {
      file_path: { type: "string", description: "The path to the file to read" },
    },
    required: ["file_path"],
  },

  execute(input: Record<string, unknown>): string {
    return readFile({ file_path: String(input.file_path ?? "") });
  },
};
```

然后在 `src/tools/index.ts` 里统一注册：

```ts
export const tools = [
  readFileTool,
  writeFileTool,
  editFileTool,
  listFilesTool,
  grepSearchTool,
  runShellTool,
];

export const toolDefinitions = tools.map(({ execute, ...definition }) => definition);
```

`executeTool` 就可以从 `switch` 改成查表执行：

```ts
const toolMap = new Map(tools.map((tool) => [tool.name, tool]));

export async function executeTool(name: string, input: Record<string, unknown>): Promise<string> {
  const tool = toolMap.get(name);
  if (!tool) return `Unknown tool: ${name}`;

  const result = await tool.execute(input);
  return truncateResult(result);
}
```

核心思路：
1. 每个工具自己负责定义 schema 和执行逻辑
2. `index.ts` 只负责收集工具对象，并导出给模型使用的 `toolDefinitions`
3. `executeTool` 只负责查找工具、执行工具、统一处理工具结果
4. 新增工具时，只需要新增工具文件，并把工具对象加入 `tools` 数组

这个写法比 `switch` 更接近多态，但不需要引入 class 体系。后续如果要补权限判断、并发安全判断、工具级 prompt，也可以继续挂到工具对象上：

```ts
type Tool = ToolDef & {
  execute: (input: Record<string, unknown>) => Promise<string> | string;
  isReadOnly?: (input: Record<string, unknown>) => boolean;
  isConcurrencySafe?: (input: Record<string, unknown>) => boolean;
};
```

## web_fetch
`web_fetch` 用来读取 URL 内容，并把结果以文本形式返回给模型。

它适合让 Agent 查文档、读取 API 响应、抓取网页中的正文信息。

```ts
export const webFetchTool: Tool = {
  name: "web_fetch",
  description: "Fetch a URL and return its content as text. For HTML pages, tags are stripped to return readable text. For JSON/text responses, content is returned directly.",
  input_schema: {
    type: "object",
    properties: {
      url: { type: "string", description: "The URL to fetch" },
      max_length: {
        type: "number",
        description: "Maximum content length in characters (default 50000)",
      },
    },
    required: ["url"],
  },

  execute(input) {
    return webFetch({
      url: String(input.url ?? ""),
      max_length: input.max_length === undefined ? undefined : Number(input.max_length),
    });
  },
};
```

工具实现：

```ts
async function webFetch(input: { url: string; max_length?: number }): Promise<string> {
  if (!input.url.startsWith("http://") && !input.url.startsWith("https://")) {
    return "Error: only http(s) URLs are supported";
  }

  const maxLength = input.max_length || 50000;
  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), 30000);

  try {
    const response = await fetch(input.url, {
      signal: controller.signal,
      headers: { "User-Agent": "mini-claude/1.0" },
    });

    if (!response.ok) {
      return `HTTP error: ${response.status} ${response.statusText}`;
    }

    const contentType = response.headers.get("content-type") || "";
    let text = await response.text();

    if (contentType.includes("html")) {
      text = text
        .replace(/<script[\s\S]*?<\/script>/gi, "")
        .replace(/<style[\s\S]*?<\/style>/gi, "")
        .replace(/<[^>]*>/g, " ")
        .replace(/&nbsp;/g, " ")
        .replace(/&amp;/g, "&")
        .replace(/&lt;/g, "<")
        .replace(/&gt;/g, ">")
        .replace(/&quot;/g, '"')
        .replace(/\s{2,}/g, " ")
        .replace(/\n{3,}/g, "\n\n")
        .trim();
    }

    if (text.length > maxLength) {
      text = text.slice(0, maxLength) + `\n\n[... truncated at ${maxLength} characters]`;
    }

    return text || "(empty response)";
  } catch (error) {
    if (error instanceof Error && error.name === "AbortError") {
      return "Error: Request timed out (30s)";
    }
    return `Error fetching ${input.url}: ${error instanceof Error ? error.message : String(error)}`;
  } finally {
    clearTimeout(timeout);
  }
}
```

核心思路：
1. 要求必须以 http:// 或 https:// 开头
2. 核心配置定义
    1. 最大内容长度定义，允许 input.max_length 设置，或走默认的 50000 
    2. 通过 AbortController 和 timeout 定义最大超时时间为 30000 ms
3. 如果 `!response.ok`，则返回 HTTP 错误信息
4. 如果 content-type 包含 html：
    1. 去掉 `<script>` / `<style>`
    2. 去掉 `HTML` 标签
    3. 简单处理 `&nbsp;`、`&amp;`、`&lt;`、`&gt;`、`&quot;`
    4. 压缩空白
5. 超过最大长度则截断，并提示截断位置
6. 返回处理后的响应信息，如果没有值则返回 `(empty response)`
7. 失败兜底
    1. 如果是 AbortError 类型错误，则提示超时 30 秒
    2. 否则默认报错
8. 无论成功还是失败，都会清理定时器

## Read-before-edit + mtime 防护
编辑文件前必须先读取，避免模型盲目修改，也避免覆盖用户在读取后做出的修改。

Agent 使用 Map 保存文件最后一次读取时的 `mtimeMs`：

```ts
private readFileState = new Map<string, number>();
```

Map 通过 `ToolContext` 传给工具。工具可以提供 `validateInput`，`executeTool` 只负责通用流程：

```ts
const validation = await tool.validateInput?.(input, context);
if (validation && !validation.ok) return validation.message;

const result = await tool.execute(input, context);
```

文件状态逻辑集中在 `file-state.ts`：

- `recordFileState`：在 `read_file`、`write_file`、`edit_file` 成功后记录最新 `mtimeMs`；记录失败时把 `Warning` 附加到工具结果
- `validateFileMutation`：修改已存在文件前检查是否读过，以及 `mtimeMs` 是否发生变化
- 新文件不存在旧状态，可以直接创建

`write_file` 和 `edit_file` 各自在 `validateInput` 中调用 `validateFileMutation`。这样新增文件修改工具时只需要修改对应工具文件，`executeTool` 不需要知道具体工具名称。

最初实现了一版，由工具内部各自处理，但这么写存在几个问题：
1. 处理逻辑分散
2. executeTool 的职责不单一，同时负责 校验和执行的职责
3. 校验职责太重了，现在集中在 executeTool这一处，即使拆出去，后续这一处统一校验还是会频繁修改，因为任一工具的校验都需要经过这个方法，不合理
4. 硬编码，和上面的相关，现在是在一个地方处理的，内部是通过判断工具名来决定行为的，这样太死板了

所以我决定调整一版，实现更优雅的设计，其核心思路是：
1. 在标准 Tool 类型里定义 `validateInput`（可选）
2. `executeTool` 只负责调用工具的通用生命周期
3. 实现公共的 validateFileMutation 和 recordFileState 方法
4. 需要文件状态能力的工具自行接入校验和记录

这样就维护起来就很舒服了：
1. 公共逻辑得到复用
2. 每个工具独立负责文件状态，添加和调整工具不影响其他模块
3. `executeTool` 职责纯粹

关键实现：

类型定义：
```ts
export type Tool = ToolDef & {
  validateInput?: ToolValidator;
  execute: ToolHandler;
};
```

executeTool 只负责调用工具的通用生命周期：
```ts
export async function executeTool(
  name: string,
  input: Record<string, unknown>,
  context: ToolContext = { readFileState: new Map() },
): Promise<string> {
  const tool = toolMap.get(name);
  if (!tool) return `Unknown tool: ${name}`;

  const validation = await tool.validateInput?.(input, context);
  if (validation && !validation.ok) return validation.message;

  const result = await tool.execute(input, context);
  return truncateResult(result);
}
```

定义公共方法
```ts
import { statSync } from "node:fs";
import { resolve } from "node:path";

import type { ToolContext, ValidationResult } from "./types.ts";

type FileMutationAction = "writing" | "editing";

export function validateFileMutation(
  filePath: string,
  action: FileMutationAction,
  context: ToolContext,
): ValidationResult {
  const { readFileState } = context;
  const absPath = resolve(filePath);
  let currentMtime: number;
  try {
    currentMtime = statSync(absPath).mtimeMs;
  } catch (error) {
    if (isFileNotFound(error)) return { ok: true };
    return {
      ok: false,
      message: `Error: Unable to inspect ${filePath}: ${error instanceof Error ? error.message : String(error)}`,
    };
  }

  if (!readFileState.has(absPath)) {
    return {
      ok: false,
      message: `Error: You must read this file before ${action}. Use read_file first.`,
    };
  }

  if (readFileState.get(absPath) !== currentMtime) {
    return {
      ok: false,
      message: `Warning: ${filePath} was modified externally since your last read. Please read_file again before ${action}.`,
    };
  }

  return { ok: true };
}

export function recordFileState(filePath: string, context: ToolContext): string | null {
  const absPath = resolve(filePath);
  try {
    context.readFileState.set(absPath, statSync(absPath).mtimeMs);
    return null;
  } catch (error) {
    return `Warning: Failed to record file state for ${filePath}: ${error instanceof Error ? error.message : String(error)}`;
  }
}

function isFileNotFound(error: unknown): boolean {
  return error instanceof Error && "code" in error && error.code === "ENOENT";
}
```

```ts
export const writeFileTool: Tool = {
  // ...
  validateInput(input, context) {
    return validateFileMutation(String(input.file_path ?? ""), "writing", context);
  },
  execute(input, context) {
    const filePath = String(input.file_path ?? "");
    const result = writeFile({
      file_path: filePath,
      content: String(input.content ?? ""),
    });
    if (result.startsWith("Successfully")) {
      const warning = recordFileState(filePath, context);
      if (warning) return `${result}\n${warning}`;
    }
    return result;
  },
};
```
