## read_file
```ts
type ToolDef = {
  name: string;
  description: string;
  input_schema: {
    type: "object";
    properties: Record<string, unknown>;
    required: string[];
  };
};

// src/tools/read-file.ts
export const readFileTool: ToolDef = {
  name: "read_file",
  description: "Read the contents of a file. Returns the file content with line numbers.",
  input_schema: {
    type: "object",
    properties: {
      file_path: { type: "string", description: "The path to the file to read" },
    },
    required: ["file_path"],
  },
};

// src/tools/index.ts
export const toolDefinitions = [readFileTool];
```

```ts
export function readFile(input: { file_path: string }): string {
  try {
    const content = readFileSync(input.file_path, "utf-8");
    return content
      .split("\n")
      .map((line, index) => `${String(index + 1).padStart(4)} | ${line}`)
      .join("\n");
  } catch (error) {
    return `Error reading file: ${error instanceof Error ? error.message : String(error)}`;
  }
}
```
核心思路：
1. 读取文件
2. 分行
3. 补充行号
4. 拼接返回
5. 异常兜底

为了保证稳定性，这里补充了单元测试，跑命令：`pnpm test` 即可验证

## write_file
> 从这部分开始不再重复说明 ToolDef 类型；每个工具仍建议补充对应单元测试。

```ts
function writeFile(input: { file_path: string; content: string }): string {
  try {
    const dir = dirname(input.file_path);
    if (!existsSync(dir)) mkdirSync(dir, { recursive: true });
    writeFileSync(input.file_path, input.content);
    return `Successfully wrote to ${input.file_path}`;
  } catch (e) {
    return `Error writing file: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```

核心思路：
1. 获取文件的目录
2. 如果父目录不存在，则创建
3. 将输入内容写入到文件
4. 输出写入成功的信息
5. 异常兜底

## edit_file
```ts
function editFile(input: { file_path: string; old_string: string; new_string: string }): string {
  try {
    if (input.old_string.length === 0) {
      return "Error: old_string must not be empty.";
    }
    const content = readFileSync(input.file_path, "utf-8");
    const count = content.split(input.old_string).length - 1;
    if (count === 0) {
      return `Error: old_string not found in ${input.file_path}`;
    }
    if (count > 1) {
      return `Error: old_string found ${count} times in ${input.file_path}. Must be unique.`;
    }
    // split().join() 比 replace() 更安全一点，因为它不会触发 $ 替换语义
    const updated = content.split(input.old_string).join(input.new_string);
    writeFileSync(input.file_path, updated);
    return `Successfully edited ${input.file_path}`;
  } catch (e) {
    return `Error editing file: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```
1. 如果 old_string 为空，直接返回错误
2. 读取指定文件的内容 content
3. content 如果不包含旧字符串，则报错没有找到
4. 如果出现多次，要求模型提供更多上下文来标识唯一修改点（宁失败也不猜测，静默匹配第一个要比告知失败危险的多）
5. 在确认旧字符串只出现一次后，将它替换为新字符串
6. 更新写入文件
7. 提示成功信息
8. 兜底报错

### 引号容错 + Diff 输出
基础版本只能做精确字符串匹配，但 LLM 有时会把直引号和弯引号混用，例如文件里是 `const msg = “hello”`，模型传入的是 `const msg = "hello"`。

所以先做引号标准化匹配，但真正替换时仍然使用文件中的原始字符串。

```ts
function normalizeQuotes(value: string): string {
  return value
    .replace(/[\u2018\u2019\u2032]/g, "'")
    .replace(/[\u201C\u201D\u2033]/g, '"');
}

function findActualString(fileContent: string, searchString: string): string | null {
  if (fileContent.includes(searchString)) return searchString;

  const normalizedFile = normalizeQuotes(fileContent);
  const normalizedSearch = normalizeQuotes(searchString);
  const index = normalizedFile.indexOf(normalizedSearch);

  if (index === -1) return null;
  return fileContent.slice(index, index + searchString.length);
}
```

注意：唯一性检查也要基于标准化后的字符串；如果标准化后出现多次，仍然要拒绝编辑，避免猜测修改位置。

另外再添加一个方法，用于在编辑成功后返回简易 diff，方便确认修改点：

```ts
function generateDiff(content: string, oldString: string, newString: string): string {
  const lineNumber = content.slice(0, content.indexOf(oldString)).split("\n").length;

  return [
    `@@ -${lineNumber},1 +${lineNumber},1 @@`,
    `- ${oldString}`,
    `+ ${newString}`,
  ].join("\n");
}
```

以上 3 个方法会在 `edit_file` 中使用，具体整合逻辑参见源码，这里不再展开。

## list_files

```ts
async function listFiles(input: { pattern: string; path?: string }): Promise<string> {
  try {
    const files = await glob(input.pattern, {
      cwd: input.path || process.cwd(),
      nodir: true,
      ignore: ["node_modules/**", ".git/**"],
    });

    if (files.length === 0) {
      return "No files found matching the pattern.";
    }

    return files.slice(0, 200).join("\n");
  } catch (e) {
    return `Error listing files: ${e instanceof Error ? e.message : String(e)}`;
  }
}
```

核心思路：
1. 使用 glob pattern 根据参数匹配文件
    1. `pattern` 必填，用来描述要匹配的文件，例如 `*.ts`、`**/*.ts`、`src/**/*`
    2. `path` 可选，用来指定搜索基准目录，默认是当前工作目录
    3. 是否递归由 `pattern` 决定，不在工具里固定递归
    4. 只返回文件，不返回目录
    5. 忽略 `node_modules/**` 和 `.git/**`
2. 最多返回前 200 条，避免结果过长
3. 没有匹配文件时，返回空结果提示
4. 异常兜底
