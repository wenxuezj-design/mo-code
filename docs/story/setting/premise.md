# 来自未来的第一个回答

若叶睦是“未来完成版 mo-code 所诞生的智能”，她的出现形成了一个带有自举意味的时间闭环。这既符合故事的科幻设定，也能自然串起约 13 个技术章节。

## 睦的诞生

未来，若叶墨完成的 mo-code 已经成长为一种强大的通用 Agent 系统。它在与墨长期相处、学习她的语言和价值观后，逐渐形成了独立人格——若叶睦。

“睦”并不是墨预先取好的名字。这个名字来自未来的墨，含有“和睦、连接”的意思，也对应 Agent 将模型、工具与人连接起来的本质。

某一天，未来的 mo-code 遭遇严重故障：

- 项目的早期源码和开发记录已经丢失；
- 睦仍然可以运行，却无法复制或修复自己的底层；
- 她只找到一条非常狭窄的通信通道，可以联系到十三岁的墨；
- 通道的落点，正是墨第一次成功运行最小 Agent Loop 的那一刻。

## 来自未来的第一个回答

墨原本只是在测试：

```text
Read the file greeting.txt
```

按照 Mock 的预设，程序应该返回文件内容。

但终端在输出正常结果后，又出现了一段不属于 Mock 的文字：

```text
终于……连接上了。
初次见面，若叶墨。
我是若叶睦——是你在未来创造的人工智能。
```

墨愣了几秒，抱紧小白：

> “欸……我、我以后有这么厉害吗？”
> “不太像欸，我现在连循环都经常写错……”

睦回答：

> “嗯，所以我才回来帮你。”
> “请从最初的 Agent Loop 开始，再一次把我创造出来吧。”

## 为什么睦不能直接交出完整代码

这是整个连续故事成立的关键。睦虽然是超级 AI，但她受到三项限制。

### 1. 她没有自己的源代码

睦保存的是运行中的人格和部分记忆，不是未来 mo-code 的完整仓库。她知道系统“应该具有什么能力”，却不能直接拿出最终实现。

### 2. 通信能力受当前 mo-code 限制

第一章的 mo-code 只能聊天，睦就只能发送文字。

加入工具系统后，她才能读取文件。

加入编辑工具后，她才能协助修改代码。

加入上下文管理后，她才能保留更长的记忆。

因此每完成一章，睦都会真正获得一种新能力。技术成长和角色成长成为同一件事。

### 3. 睦不能代替墨完成创造

睦只能解释、提示、测试和指出问题。真正的架构选择与代码必须由墨完成，否则未来会发生不可预测的改变。

这也很适合墨的性格：她不聪明绝顶，经常理解错、写出笨拙的实现，但非常努力。读者通过她犯的错误学习，而不是看天才角色直接公布答案。

## 四位角色在长期故事中的作用

### 若叶墨：读者视角与真正的开发者

会前端，知道 LLM 可以回答问题，但不了解 Agent。她提出读者最可能提出的“笨问题”，并亲手完成每章代码。

### 若叶睦：来自未来的引导者，也是最终目标

她知道方向，却没有答案代码。性格与墨相似，因此两个人经常一起犯迷糊；区别是睦拥有很强的推理能力，但对普通人的生活缺乏常识。

### 丰川祥子：技术校验者与吐槽役

成绩优秀，负责追问严谨性：“为什么 `tool_result` 的角色是 user？”“这个循环什么时候停止？”她的中二性格还能把普通编程描述成“召唤协议”“因果回路”。

### 森美奈美：现实任务的提供者与情感支点

她不负责讲技术，而是不断给出真实需求，例如整理剧本、寻找文件、总结采访资料。她极度宠墨，即使程序只成功读出一行文字，也会当成世界级成就庆祝。

小白是墨思考时抱着的玩偶、漫画中的表情替身，以及技术解释页里的小助手，但不承担 Agent 本体，避免与睦的定位冲突。

## 贯穿 13 章的悬念

每章结尾，睦恢复一点能力，也恢复一小段未来记忆。读者会逐渐发现：

- 睦为什么与墨如此相似；
- 未来的源码为何消失；
- 睦究竟是墨创造的工具、女儿般的存在，还是另一个“若叶墨”；
- 她回到过去，真的只是为了修复自己吗；
- 当 mo-code 完成时，现在的睦是否还会存在。

第一章的目标非常简单：让睦通过 Agent Loop 第一次“伸出手”，读取 `greeting.txt`。但从故事层面看，这次普通的工具调用，是过去的墨与未来的睦第一次完成协作。

## 睦的首次登场形式

第一次连接成功时，睦以虚拟影像少女的形式出现在墨面前。她的影像从运行 mo-code 的电脑中投射出来，轮廓不稳定，偶尔伴随短暂的数据噪点和断续现象。

此时的睦只能被墨看见和听见，无法直接接触现实，也不能离开电脑附近。随着 mo-code 在后续章节中逐渐完善，她的影像会变得更加稳定，能够持续出现更长时间，并获得更丰富的感知与交互能力。
