# 文件系统访问目标与权限规则目标分离

工具权限描述同时保留用于规则匹配的 `permissionTarget`，并新增独立的 `filesystemAccesses` 描述实际读取、写入或删除的路径。路径门禁只消费文件系统访问目标，不从权限规则字符串或工具名称反推文件行为。

两类目标不能合并：Shell 的规则目标是完整命令，`list_files` 的规则目标包含 glob，而 `mv`、`cp` 等调用还会同时访问多个路径并具有不同操作方向。分离后，工具和有限 Shell 分析器负责声明访问事实，统一路径模块负责真实路径、目录边界和保护路径判断。

文件访问描述使用三态：字段不存在表示该工具不参与本期路径分析，`known` 携带一个或多个 `read`、`write`、`delete` 目标及递归删除标记，`unknown` 表示本次路径无法被完整可靠地解析。只有 `unknown` 会触发不可记忆的保守确认，避免把“未纳入分析”和“分析失败”混为一谈。`unknown` 可以附带已经确定的部分访问事实，也可以标记无法枚举目标的潜在灾难删除；这些信息只用于灾难删除熔断，不能把整次调用提升为可自动放行的 `known`。

`list_files` 只有在 glob 位于文件名部分时，才以固定目录作为已知访问范围，例如 `src/*.ts`。如果 glob 出现在目录部分，例如 `**/*.ts` 或 `*/index.ts`，动态目录可能命中无法预先确认的目录或符号链接，因此本阶段保守返回 `unknown`，不宣称静态前缀足以证明实际访问范围。`glob` 会先按词法路径处理 pattern 中的 `..`，访问描述使用相同的实际搜索根；Shell 文件命令则保留未折叠路径交给 `PathBoundary` 按真实文件系统顺序处理。

`ToolContext.cwd` 是权限检查和实际执行的唯一相对路径基准。内置文件工具使用与访问描述相同的绝对目标，`run_shell` 也显式使用该目录执行，不再依赖工具进程的隐式 `process.cwd()`；这避免检查目标与执行目标分离。

`PathBoundary` 集中解析这些目标并报告主工作目录、外部路径、保护路径、无法解析和灾难删除等事实，但不直接返回 `allow`、`ask` 或 `deny`。最终行为仍由 `PermissionRulePolicy` 组合路径事实、显式规则、权限模式和 Shell 语义。

多目标调用按最严格事实整体裁决，不尝试部分执行。有文件系统访问的 read-before-write、mtime 等状态校验移动到授权之后，避免校验器在权限门禁前访问目标元数据。
