# 项目信任在 Agent 构造前过滤权限扩张配置

项目信任是配置来源门禁，不是单次工具权限。mo-code 必须先根据用户侧信任状态过滤项目配置，再用生效配置构造 Agent、权限模式和规则策略；不能等到工具调用进入 `PermissionGate` 后才补做信任判断，否则项目 `defaultMode` 已经可能提前扩大权限。

未信任时，用户级配置以及项目级、本地项目级的 `deny`、`ask` 继续生效，项目级和本地项目级的 `allow`、`defaultMode` 被忽略。交互式 CLI 可以在 Agent 构造前请求信任；非交互运行和直接构造 Agent 时只读取已有信任记录，没有记录就采用受限项目会话。

信任按规范化的信任根记录在用户目录中：Git 项目使用最近的仓库根，非 Git 项目使用启动目录。信任根同时限制项目配置的向上发现范围，但不会扩大主工作目录的文件访问范围。直接从用户 Home 启动时，接受只对当前进程有效，不写入持久记录。
