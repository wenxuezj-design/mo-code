# 主工作目录使用 Agent 启动目录

mo-code 把启动 Agent 时的当前工作目录及其子目录作为主工作目录，不因发现 Git 仓库根目录或项目配置根目录而自动扩大文件访问范围。用户在仓库子目录启动 Agent 时，意味着默认只授权该子目录，而不是无感授权整个仓库。

Git 根目录仍可用于定位项目配置，但配置归属和文件访问授权是两个独立概念。需要访问主工作目录之外的文件时，应通过后续明确设计的目录授权流程处理。

主工作目录之外的普通路径不是永久禁区。在允许交互确认的模式下，访问外部路径需要额外确认；`dontAsk` 无法确认，因此拒绝该访问。普通的编辑会话授权只适用于主工作目录内，不能自动跨越目录边界。

用户可以通过匹配具体工具和路径的显式 `allow` 规则预先授权普通外部路径。显式 `deny` 和 `ask` 仍优先于 `allow`；没有匹配规则时才回退到外部路径的默认确认。这一能力不适用于另行定义的保护路径。
