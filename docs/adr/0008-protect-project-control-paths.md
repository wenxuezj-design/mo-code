# 保护项目控制路径的最小集合

mo-code 把 `.git/`、`.gitmodules`、`.mo-code/`、`.claude/`、`CLAUDE.md` 和 `AGENTS.md` 定义为保护路径。这些路径分别控制仓库元数据、权限配置和 AI 行为，修改它们会影响后续工具调用或开发流程，因此不能与普通项目文件采用相同的自动授权语义。

Claude Code 还保护 IDE、包管理器和构建工具等更大的配置集合。本项目以快速复现核心机制为目标，先保护与仓库和 Agent 直接相关的最小集合；未来可以扩充清单，但不在本阶段实现通用敏感文件分类。

保护语义只针对修改操作。读取这些路径仍遵循普通读取权限和工作目录边界；确实不应读取的文件由显式 `deny` 规则限制，而不把“控制文件”和“机密文件”混为同一概念。

普通 `permissions.allow` 和 `edit:*` 会话授权不能跳过保护路径。`default` 与 `acceptEdits` 中每次修改都需要重新确认且不能记忆，`dontAsk` 与 `plan` 中直接拒绝，从而避免普通文件编辑授权意外扩大到仓库元数据或 Agent 配置。

`bypassPermissions` 是保护路径的模式例外：用户显式启用该模式后，可以修改保护路径，不再弹出保护确认。这与 Claude Code 当前行为及本项目既有 bypass 语义保持一致；灾难性目录删除仍由独立熔断处理。

保护名称在任意目录层级生效，而不只匹配主工作目录根部。链接位置或真实目标中的任一组件命中 `.git`、`.mo-code`、`.claude`，或任一文件名命中 `.gitmodules`、`CLAUDE.md`、`AGENTS.md`，都采用保护路径语义；这可以覆盖嵌套仓库和子项目配置。

保护名称按大小写不敏感方式比较，避免大小写不敏感文件系统中的 `.GIT`、`agents.md` 等别名绕过同一文件的保护语义。
