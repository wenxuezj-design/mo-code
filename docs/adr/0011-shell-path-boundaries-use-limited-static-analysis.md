# Shell 路径边界使用有限静态识别

mo-code 的路径权限门禁完整覆盖内置文件工具，并对能够可靠解析字面路径的常见 Shell 文件命令应用相同边界。变量、通配符、脚本解释器和复杂 Shell 语法无法确定实际访问目标时，不把命令判定为路径安全，继续回退到询问或拒绝。

本项目不实现完整 Bash AST 或 OS 级文件系统沙箱。有限识别可以阻止常见的工作目录外访问、保护路径修改和灾难删除，同时保留核心机制的可读性；获准执行的任意 Python、Node 或其他子进程仍可能自行访问文件系统，这一限制必须在实现笔记中明确说明。

首批提取路径的读取命令为 `ls`、`cat`、`head`、`tail`、`grep`、`rg`、`find` 和 `stat`；修改命令为 `rm`、`mv`、`cp`、`mkdir`、`rmdir` 和 `touch`。`sed`、`dd`、`tee`、`install`、脚本解释器及 Git 内部文件访问暂不纳入路径提取。

对于首批支持的命令，路径包含变量、命令替换或其他无法可靠解析的表达式时，普通 `allow` 也不能自动放行：交互模式逐次确认且不能记忆，`dontAsk` 与 `plan` 拒绝，`bypassPermissions` 仅受灾难删除熔断约束。未纳入首批集合的任意脚本和命令继续使用既有权限行为，不宣称受到完整路径保护。

现有只读分类中的 `wc`、`file`、`du`、`df` 暂不增加路径提取，但只要带有可能表示路径的参数，就返回未知文件访问计划并进入保守确认；无路径形式仍保留原有只读行为。`pwd`、`echo`、`printf`、`which` 等明确没有文件目标的命令不受影响。

现有 Shell 分类入口深化为一次性分析：同一轮扫描同时产出只读或修改语义、文件系统访问计划、无法解析状态和递归删除信息，不维护两套可能漂移的分词逻辑。

分析采用 fail-closed：未知选项、无法确定参数归属、复合命令、重定向或前置环境变量只要不能完整证明访问范围，就把整个文件访问计划降为 `unknown`。BSD 与 GNU 对同一选项的“是否携带值”存在冲突时，选择不会吞掉后续真实路径的保守解释；代价是少数平台上可能多询问一次，而不是错误自动放行。递归读取同时允许跟随目录内符号链接时，起始目录不足以证明边界，也统一回退到 `unknown`。

`acceptEdits` 自动允许 `rm`、`mv`、`cp`、`mkdir`、`rmdir` 和 `touch` 中能够可靠解析、且全部目标位于主工作目录普通路径内的调用。外部路径、保护路径、无法解析目标和灾难删除仍按更高优先级处理。
