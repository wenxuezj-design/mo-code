# 路径边界同时检查链接位置与真实目标

mo-code 在判断主工作目录、外部路径和保护路径时，同时检查用户传入的路径位置与符号链接解析后的真实目标。自动放行要求两者都位于允许范围；任一侧落入保护路径，修改操作就采用保护路径语义。

只检查传入路径会允许工作目录内的链接指向外部或保护路径；只检查真实目标则会让外部链接借由指向工作目录逃过边界确认。同时检查两者与 Claude Code 的核心语义一致，也使显式路径规则不因符号链接而静默扩大。

对于已经存在的目标，直接解析完整真实路径；对于尚未创建的文件，从目标向上找到最近的已存在祖先，解析该祖先后再拼接剩余路径。这样创建文件前也能发现父目录符号链接指向外部或保护位置；无法可靠解析时不能自动放行。

文件权限规则也同时考虑两种路径身份：`allow` 要求链接位置和真实目标分别获得允许，`deny` 或 `ask` 则在任一侧命中时生效。保护路径同样采用任一侧命中即保护，防止表面路径规则通过符号链接静默扩大权限。

边界需要用户确认时，提示会展示触发类型、请求路径，以及与其不同时的真实目标；多路径命令只列出触发边界的目标。用户由此确认实际访问位置，而不必仅凭完整命令自行推断符号链接结果。

本阶段不防御路径检查完成后、工具执行前由其他进程替换符号链接的竞态。解决该问题需要文件描述符级访问或 OS 沙箱；当前实现定位为工具执行前的应用层路径门禁，不承诺文件系统级隔离。
